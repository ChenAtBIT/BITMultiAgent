会议名称：实验室多 Agent 系统周会
会议时间：2026-06-05 14:00-15:20
会议地点：信息楼 503 / 腾讯会议
主持人：陈老师
参会人员：陈老师、李晨、王敏、赵宇、刘航

会议背景：
本周主要讨论动态 DAG Multi Agent 系统的阶段成果、MCP 工具扩展，以及下周对外演示的准备事项。

议题一：当前开发进展同步
陈老师：目前 Agent Designer、Planner、DAG Runtime 主链路已经打通，串并行混合计划和节点 Retry 的演示效果基本稳定。
李晨：RAG-MCP 的工具检索已经可以工作，但工具描述还需要再优化，不然有时候会把无关工具也召回。
王敏：README 里部署流程已经比较完整，不过新增 Agent 时还没有统一的同步规范，后续最好把架构图、启动脚本、部署步骤一起维护。

议题二：会议资料处理能力确认
陈老师：后续希望动态 DAG Agent 能通过 MCP 读取会议记录，并生成一份 Markdown 纪要，最好还能落盘保存。
赵宇：需要保留会议文件 MCP 工具，至少要能读取本地文本文件、推导默认输出路径、把生成结果写成 md 文件。
刘航：如果会议记录比较长，读取工具最好支持分段读取，不然一次性塞给模型可能不稳定。
李晨：纪要内容建议固定几个段落，至少有会议主题、核心结论、行动项、风险和后续安排。
陈老师：行动项里尽量识别负责人和截止时间，没有就写未明确，不要硬编。

议题三：下周演示准备
王敏：我负责把样例会议文件放到项目 docs/examples 目录，方便测试和演示。
赵宇：我负责设计 MCP 与 DAG Agent 的工具适配接口，并更新 README 的完整部署步骤。
李晨：我负责补一轮端到端测试，至少走一遍 start_system.sh、动态规划、DAG 执行和 Retry 的完整链路。
陈老师：演示时要覆盖三类场景，数学计算、服务器巡检、会议纪要生成。

讨论中的风险与问题：
1. 如果会议文件不是纯文本格式，现阶段工具可能无法直接读取。
2. MCP 尚未接入 DAG Runtime，当前演示不能宣称 Agent 已具备工具调用能力。
3. 动态 Agent 的日志目录和运行状态需要统一管理，否则排查问题会很麻烦。

最终结论：
1. 保留会议文件 MCP 工具，并在接口稳定后接入动态 DAG Agent。
2. 纪要输出格式统一为 Markdown。
3. 演示测试需要覆盖“生成并写入纪要文件”这一完整闭环。
