MCP Server Learning Map

先把 MCP-Server 这一层学透

这份页面专门为这个仓库写，目标不是泛泛介绍 MCP，而是帮你顺着真实代码看到： Agent 是怎么发现工具、怎么发起 tools/call、 mcp_server 又是怎么把请求路由给插件的。

学习顺序 先看哪里，后看哪里，避免一上来迷路。 调用全链路 一条工具调用从 Agent 走到插件的完整路径。 对象与函数 核心类、重要方法、作用边界。 JSON 示例 真正发出去的 JSON-RPC 请求与插件返回格式。

学习路线

推荐你沿着“配置入口 → Agent 封装 → Client 通信 → Server 分发 → Plugin 执行”这条线读，不要先钻 RAG 或全部插件。

第 1 步：先看配置入口

搞清楚 MCP 是怎么被打开的，路径和插件目录怎么传进去。

  1. examples/ai_orchestrator/start_system.sh
  2. mcp/src/mcp_agent_integration.cpp 里的 parseMCPConfigFromArgs()
  3. parseMCPConfigFromEnv() 看环境变量兜底

第 2 步：看 Agent 如何“用 MCP”

这一层最适合新手，因为它离业务最近，也最容易看出调用意图。

  1. MCPAgentIntegration::initialize()
  2. MCPAgentIntegration::getAvailableTools()
  3. MCPAgentIntegration::callTool()
  4. MathAgent::tryMCPCalculation()

第 3 步：看 Client 如何和 MCP Server 通信

这里是“真正发请求”的地方，默认是本地子进程 + STDIO，不是直接 HTTP。

  1. MCPClient::connect()
  2. MCPClient::startMCPServer()
  3. MCPClient::listTools()
  4. MCPClient::callTool()
  5. buildJSONRPCRequest() / parseJSONRPCResponse()

第 4 步：看 Server 和插件如何接住请求

这一步会让你真正明白 MCP-Server 不是“黑盒”，而是一个方法分发器 + 插件宿主。

  1. mcp_server_integrated/src/main.cpp 的 OverrideCallback("tools/list")
  2. OverrideCallback("tools/call")
  3. PluginsLoader::LoadPlugin()
  4. PluginAPI 和插件里的 HandleRequest()
先学计算器插件最划算，因为它没有外部网络依赖，返回值也最容易读。
RAG 是“选哪个工具”的增强层，不是 MCP 基础调用链的第一站。
这个项目默认主路径是 STDIO 子进程模式，SSE 传输是可选能力。

一条调用怎么走

以数学题 1+7 为例，重点看调用对象和方法名，不先纠结所有业务细节。

Step 1
MathAgent

tryMCPCalculation(question) 决定要不要用 MCP，并构造 {"expression": "1+7"}。

Step 2
MCPAgentIntegration

callTool("calculator", args) 检查工具缓存、重试策略，再委托给工具管理器。

Step 3
MCPToolManager / MCPClient

executeTool() → MCPClient::callTool()，发出 JSON-RPC 方法 tools/call。

Step 4
mcp_server

Server::HandleRequest() 命中 tools/call 回调，遍历插件，找到工具名匹配的插件。

Step 5
Calculator Plugin

HandleRequest() 读取 params.name 和 params.arguments，执行计算，返回 JSON 文本。

最重要的理解

  • Agent 不会直接调用 Calculator.cpp。
  • Agent 调的是 MCPAgentIntegration，它再调 MCPClient。
  • MCPClient 默认会 fork + execv 一个本地 mcp_server 进程，并通过管道通信。
  • mcp_server 再根据工具名把请求转交给某个插件的 HandleRequest()。

你最该先记住的 JSON-RPC 方法

tools/list tools/call prompts/list prompts/get resources/list resources/read notifications/message

学习 MCP 调用链时，前两个最关键，后面可以第二轮再看。

配置入口长什么样

这一段很重要，因为它解释了为什么 Agent 知道该启动哪个 mcp_server，也解释了插件目录是怎么传进去的。

# start_system.sh 里拼出来的 MCP 参数
MCP_ARGS="--enable-mcp --mcp-server $MCP_SERVER_PATH \
--mcp-args -l,$MCP_LOGS_PATH,-p,$MCP_PLUGINS_PATH"
// parseMCPConfigFromArgs()
if (arg == "--mcp-server") {
  config.mcp_server_path = argv[++i];
  config.enable_mcp = true;
} else if (arg == "--mcp-args") {
  // 用逗号拆分，得到 -l logs -p plugins
}

这意味着什么

  • Agent 本身不内置工具，它只是拿到 mcp_server 路径与参数。
  • -p 指向插件目录，所以 Server 启动后能批量发现 .so。
  • -l 只是日志目录，不参与工具调用逻辑。

你最先应该验证的点

  • mcp_server 二进制路径是否存在。
  • 插件目录里是否真有 .so 文件。
  • tools/list 能否列出工具名，比如 calculator。

你会看到的 JSON

先盯住 tools/list 和 tools/call 这两个请求格式，理解起来最快。

1. Client 发给 Server 的 tools/call

{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "id": "call_tool_1712345678",
  "params": {
    "name": "calculator",
    "arguments": {
      "expression": "1+7"
    }
  }
}

2. 计算器插件返回给 Server 的结果体

{
  "content": [
    {
      "type": "text",
      "text": "1+7 = 8"
    }
  ],
  "isError": false
}

3. Server 回给 Client 的 tools/list 样式

{
  "jsonrpc": "2.0",
  "id": "list_tools_1712345678",
  "result": {
    "tools": [
      {
        "name": "calculator",
        "description": "Evaluates a mathematical expression",
        "inputSchema": {
          "type": "object",
          "properties": {
            "expression": { "type": "string" }
          },
          "required": ["expression"]
        }
      }
    ]
  }
}

4. Agent 侧最常见的调用代码

json args;
args["expression"] = question;

auto result = mcp_integration_->callTool(
  "calculator",
  args.dump()
);

if (result.success) {
  return result.result;
}

内置插件怎么看

先看 calculator，再看有通知或外部 API 的插件。学习成本会低很多。

最适合入门：Calculator

  • 工具名：calculator、add、subtract、multiply、divide、power、sqrt、factorial
  • 优点：无网络依赖，参数简单，返回文本直观。
  • 重点看：methods[] 和 HandleRequest() 里的 toolName 分支。

第二轮再看：Weather

  • 工具名：get_weather
  • 重点：插件内部还能继续发 HTTP 请求，不只是本地计算。
  • 适合理解“插件里可以封装外部服务”。

进阶：Notification

  • 工具名：progress_test、logging_test
  • 重点：notifications->SendToClient() 如何主动推送进度。
  • 适合理解 MCP 不只是 request-response。

最简案例：Sleep

  • 工具名：sleep
  • 重点：参数读入、执行、返回三段式最清楚。
  • 适合你仿写自己的第一个插件。

一句话总结

把 MCP-Server 想成“本地工具总线”：Agent 负责发起，Client 负责传输，Server 负责分发，Plugin 负责真正干活。

先背下来的主链路

MathAgent::tryMCPCalculation()
  -> MCPAgentIntegration::callTool()
  -> MCPToolManager::executeTool()
  -> MCPClient::callTool()
  -> mcp_server (tools/call)
  -> PluginAPI::HandleRequest()
  -> Calculator::HandleRequestImpl()

你下一步最值得做的练习

  • 手动追一次 calculator 的调用链。
  • 把 sleep 插件读懂，看它如何读取参数。
  • 然后仿照它写一个最小工具，比如 echo_text。
